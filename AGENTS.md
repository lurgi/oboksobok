# Project Rules

- Keep project-specific styling for UI and layouts authored in this project in components with CSS Modules, instead of putting scoped styles directly in Astro pages.
- Astro pages should compose layouts and components, while styled UI/layout units live under `src/components`.
- Keep `src/styles/global.css` limited to font imports, design tokens, and base element defaults. Do not put project-specific layout, header, or page classes there.
- Put shared page-shell styling in a component such as `PageLayout`, and put content width constraints on the content component that owns that width.
- Keep overrides for HTML generated by external renderers in dedicated CSS files, scoped beneath a project-owned root class. Keep `react-notion-x` overrides in `src/styles/notion-renderer.css` beneath `.oboksobok-notion`; do not spread them across CSS Modules.
- Keep each element's style overrides in one place, and reuse existing design tokens before introducing new ones.
- Use CSS Module `:global()` selectors only when targeting external classes or shared state classes.
- Investigate syntax, configuration, and tool versions before suppressing lint diagnostics. If an exception is necessary, document its reason and limit it to the smallest applicable scope.
